# HubSpot Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: маркетолог/
RevOps-специалист SMB.

## 1. Credential type
API key (Private App access token, одно поле + опциональный label).

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` со ссылкой на "Settings > Integrations > Private
   Apps" и явным списком нужных scopes по каждой функции приложения (CRM read/write,
   marketing events, tickets) — сгруппировано по тому, что пользователь реально
   собирается делать, а не единый список из 40 scopes.
2. **Форма** — Access token (password-type input) + необязательный "Friendly name"
   (полезно, если у агентства несколько HubSpot-порталов клиентов).
3. **После успеха** — `sync_check` мгновенно (портал id/домен) + `get_pipeline_health`
   без доп. клика — обе value-add функции сразу, не один "успешно подключено".
4. **Multi-portal** — идеально: список всех подключённых порталов с быстрым
   переключателем (агентское использование — частый сценарий для HubSpot).
5. **Scope insufficient** — если токен не имеет прав на конкретный объект (custom
   object, marketing email) — конкретный алерт "не хватает scope `X`", а не общая
   403-ошибка, с прямой ссылкой куда добавить scope в Private App.
6. **Истечение** — Private App токены НЕ истекают сами по себе (в отличие от
   стандартного HubSpot OAuth) — единственный failure mode это ручной revoke на
   стороне пользователя; сообщение об ошибке должно явно называть это ("токен был
   отозван вручную в HubSpot — переподключите"), не путать с "истёк по времени".
